# Current Design Handoff

## Status

This document is the entry point for A5 and any visual-design work. The
canonical product implementation is `origin/main`. Historical screenshots,
including files under the local `ANIMATION INSPO` folder, are not product
requirements and are not current interface references.

Before design work:

```bash
git fetch origin
git switch main
git pull --ff-only origin main
git status --short --branch
```

Do not design against an older agent branch or a saved screenshot without first
checking the current product.

## Canonical Journey

The interface must preserve one workflow:

```text
Landing
-> Trial Demo
-> FIND: evidence and requirement intake
-> buyer-reviewed Need Profile and recommended solutions
-> CONNECT: explainable matches and approved outreach
-> private supplier response
-> buyer comparison and selection
-> DEPLOY: Pinch commitment and delivery visibility
```

The buyer and supplier screens are role-specific views of the same commercial
record, not separate products.

## Capture Rules

1. Capture UI only from current `main` or the current deployed site.
2. Start a fresh trial with `?start=new` before recording the buyer intake.
3. Generate supplier links through the current Connect flow.
4. Do not reuse screenshots from `ANIMATION INSPO/ui` or
   `ANIMATION INSPO/website`.
5. Do not invent payment success, delivery states, or supplier responses for a
   screenshot. Reach each state through the running demo.
6. Record the commit SHA and route used for every new reference capture.

## Design Boundaries

- Preserve the working API contracts and end-to-end state transitions.
- Keep one dominant action per state.
- Keep FIND, CONNECT, and DEPLOY visible as the persistent journey.
- Distinguish the private supplier view without making it appear to be another
  product.
- Treat real hosted Pinch checkout and authoritative payment confirmation as
  separate states.
- Validate desktop and mobile layouts and check browser console errors before
  handing work back to A0.
