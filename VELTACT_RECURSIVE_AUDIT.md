# Veltact Recursive Product Audit

## Audit scope and guardrails

- Audit date: 2026-07-27 (Australia/Sydney)
- Required branch: `Recurssion`
- Product entry: `/landing.html` (also served from `/`)
- Primary workflow: canonical Find, Connect, Deploy workspace (`/index.html`)
- Secondary workflow: guided legacy V2 workspace (`/v2.html`)
- Supplier workflows: canonical private response (`/supplier.html`) and legacy V2 claim (`/supplier-claim.html`)
- External-call exclusions: real SMS, email, OpenAI, Firecrawl, and Pinch transactions are not invoked. Their controls and integration points remain present. Local fixtures and documented local-demo transitions are used to keep the workflow testable.
- Test perspective: first-time buyer and first-time supplier, with direct-route, invalid-input, refresh, back-navigation, duplicate-action, error, responsive, keyboard, accessibility, and persistence checks where reachable.

## Environment and architecture baseline

The repository is an npm workspace with shared Zod contracts, a TypeScript/Express API, and dependency-free TypeScript frontends compiled to static assets served by the API. Marketplace and V2 workflow state are persisted to local JSON files under `apps/api/.data/`. The initial checkout already contained uncommitted product work; it was preserved and moved intact onto the required audit branch before any audit edits.

## Remaining limitations and production-readiness notes

- Real provider behavior was deliberately not exercised. Pinch webhooks/reconciliation, outbound email/SMS, and live OpenAI/research must be validated in provider sandboxes with dedicated non-production credentials before release; this audit makes no claim that those external calls were tested.
- Fixture/local-demo evidence is intentionally non-authoritative. It cannot prove supplier identity, qualifications, availability, delivery, payment, or technical feasibility.
- The repository has no automated browser E2E, formatter, coverage, dependency-audit, or aggregate `check` script. Current `lint` is TypeScript `--noEmit`, and the contracts workspace has no standalone test command.
- Browser validation covered keyboard/semantic behavior, responsive overflow, direct routes, errors, polling, refresh, persistence, and the principal first-user paths, but did not include a dedicated screen-reader session or automated accessibility scanner.
- JSON-file persistence is appropriate for the prototype/audit runtime, not a production multi-instance datastore. Production deployment still requires durable database, concurrency, backup, retention, and secret-management decisions.
- The named recovery stashes were retained rather than deleted, and unrelated user artifacts were left untouched and excluded from delivery.
